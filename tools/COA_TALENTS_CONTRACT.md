# CoA talent rendering — data contract

Two datasets let coalogs draw a CoA character's talent tree. CoA does **not** use
the classic 3-tab talent API or retail `C_Traits`; it uses Ascension's custom
`C_CharacterAdvancement` node system. The ConLogs-CoA addon (v0.2.4+) captures
both halves.

## 1. Tree layout — `coa_talent_tree.json` (this folder)

The blank map: every node for every class/spec. Static — capture once per game
patch. Generated by `extract_coa_talent_tree.py` from the addon's
`ConLogsTalentTreeDB.coaExport` SavedVariable (`/conlogs dumpentries` in-game).

```json
{
  "version": "0.2.4",
  "capturedAt": 1783499673,
  "locale": "enUS",
  "count": 11834,
  "nodes": [
    {
      "id": 1,                    // node id — the key characters' picks reference
      "name": "Blizzard",
      "icon": "spell_frost_icestorm",   // lowercase icon basename → your CDN
      "desc": "...",              // tooltip text (may be absent)
      "type": "Talent",           // "Talent" | "TalentAbility" | "Ability"
      "nodeType": "SpendSquare",  // shape: SpendSquare | SpendCircle | SpendHex (choice)
      "maxRank": 1,
      "spells": [10],             // spellID per rank
      "class": "Mage",            // grouping key (DBC name, e.g. "Necromancer")
      "tab": "Frost",             // spec grouping key (e.g. "Geomancy")
      "x": 4, "y": 2,             // grid position, custom/hero classes (x:0–10, y:0–9)
      "col": 0, "row": 2,         // grid position, default/reborn classes
      "connected": [7533, 7801],  // THE TREE EDGES: node ids this node links to (draw a line to each)
      "group": 0,                 // choice-node group key: nodes sharing a nonzero group are one choice slot
      "parent": 0,                // legacy/hero visual edge source (usually 0 — prefer `connected`)
      "anchor": "TOP", "color": "TEAL", "distance": 0,   // legacy edge hints
      "requires": [],             // logical prereq ids (sparse — NOT the visual edges; use `connected`)
      "aeGate": 0, "teGate": 0,   // essence investment gates for the tab
      "reqLevel": 20,
      "disabled": true,           // present only when true
      "hidden": true              // present only when true
    }
  ]
}
```

### Rendering guidance
- **Group** nodes by `class` + `tab`. Each (class, tab) pair is one tree page
  (e.g. `Mage`/`Frost`, `Primalist`/`Geomancy`). ~89 specs across 43 classes.
- **Position:** use `x`/`y` if either is non-zero (custom/hero classes — an
  integer grid, x:0–10 columns, y:0–9 rows), else `col`/`row` (default/reborn).
  Map grid coords to pixels (e.g. `px = x * colWidth`, `py = y * rowHeight`).
- **Edges = `connected`** — for each node, draw a line to every node id in its
  `connected[]` array. That reproduces the actual tree's connecting lines
  (~3500 nodes carry them). Do NOT use `parent`/`requires` for this — they're
  near-empty; `connected` is the real edge set. (Ignore `anchor`/`color`/
  `distance`/`parent` unless you want to match the client's exact curve style.)
- **Choice nodes:** nodes sharing a nonzero `group` occupy one slot as a choice
  (the character picks one). Render them as a split/choice node at that position.
- **Node shape** from `nodeType`: `SpendSquare` (square), `SpendCircle` (circle),
  `SpendHex`/choice (hexagon/diamond).
- **Filter out non-tree entries:** ~2537 nodes have no position at all — these
  are spellbook/class-wide abilities, not tree nodes. Skip them. Also skip junk
  buckets: `tab` in `{None, INVALID_TAB_TYPE_0, party}` or `class` in
  `{None, party}` (~126 nodes), and optionally `disabled`/`hidden` nodes.
- (Legacy, ignorable) some older notes referred to grid-adjacency edges and
  `requires[]`/`parent` links — superseded by `connected` above.
  `parent`/`anchor`/`color`/`distance` give explicit visual edges (~19 nodes,
  mostly custom classes). Draw grid first; overlay explicit links where present.
- **Icons:** `icon` is a lowercase basename like `spell_frost_icestorm`. Map to
  your icon CDN (e.g. `.../<icon>.jpg`). 95% resolve; a few customs are null.

## 2. Character selection — relay field `player.coaTalents`

Per character, which nodes they picked and to what rank. Captured every scan,
carried on the ConLogs relay/mesh, stored per set as `caBuild`, wire format
`"L:"+nodeId:rank,nodeId:rank,...`. Decoded, it is exactly:

```json
"coaTalents": { "29263": 3, "29265": 1, "7608": 1, ... }   // nodeId → rank
```

`caSpec` (a small int) accompanies it = the character's active spec index.

**Render** = for each (class, tab) tree, draw `nodes[]`, then fill/highlight
every node whose `id` is a key in `coaTalents`, showing `rank`/`maxRank`.

## Known gap: geomancy / Wildwalker

`geomancy` is a spec of the **Wildwalker** class (DBC `Primalist`). This export
has **no Wildwalker/Primalist nodes at all** — that class isn't present in this
client build's `C_CharacterAdvancement.GetAllEntries()` (unreleased or
realm-gated here). It's a client-content gap, not a capture bug: re-run
`dumpentries` on a client/realm where Wildwalker is active to pick it up.
